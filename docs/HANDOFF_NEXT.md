## 2. Как устроена работа (проверено)
- **Помощники в worktree.**
  - Создать: `git worktree add ../pirates-X -b batch-X`.
  - Скопировать в новое дерево `node_modules` и `assets/raw/{qa,audit,center}.js`.
  - Выдать каждому помощнику свой порт сервера: 586xx–587xx, не 58521 и не 58530.
  - Одновременно — не больше двух помощников, и только на непересекающихся областях. Бой (`tacbattle.ts`) трогает только один из них.
  - После работы: `git merge --no-edit batch-X`, затем `npm run check`, пуш, `git worktree remove --force ../pirates-X`, `git branch -D batch-X`.
  - Каждый промт помощнику повторяет правила из §0. Дополнительные пункты давать **прямо в промте** нового помощника, а не через `SendMessage`: однажды система безопасности приняла такое сообщение за подмену инструкций и заблокировала работу.
- **Конфликты слияния.**
  - Использовать `python assets/raw/audit/resolve3.py <files...>`: трёхсторонний разбор `diff3` по символам. Добавления обеих сторон он сводит сам, а при пересекающихся правках падает с ошибкой.
  - Старый `resolve.py` **не использовать**: он склеивал соседние строки.
  - После слияния проверить: таблицу `TABLE` в `client/src/lang/server.ts` (все `...SERVER_RU_*`), `type Modal` в `client/src/main.ts`, импорты.
- **HELP админки.** Строка `HELP` в `server/src/game/admin.ts` и её русская пара в `client/src/lang/server.ru.admin.ts` должны совпадать **команда в команду**, это проверяет тест.
  - После каждого слияния пару пересобирают скриптом: собрать соответствия «команда EN → RU» из обеих родительских версий и составить русскую строку по текущему английскому HELP. Пример есть в истории коммитов слияний.
- **Детерминизм.**
  - Тесты прогоняют общий `game.rng`, поэтому у каждой новой случайной системы должен быть **свой `Rng`**. Образец — `ar()` в `server/src/game/auction.ts`.
  - Новые объекты мира **только дописываются** в конец (`legacyWorld` и `legacyIslands`), id старых не меняются.
  - Время берётся из `game.wallNow()`. Не привязывать тесты к реальной дате — так однажды сломалась «рыба дня».
- **Баланс.**
  - Лестница D12 и `tests/balance/` должны оставаться зелёными.
  - Ориентир дохода — `seaHour(L)` в `tests/balance/island.ts`.
  - Стабильные цели: равный бой ≈ 50 %; при 10 % меньше бойцов поражение 65–75 %; обычный экипаж против пиратов своего уровня 45–55 % на каждом уровне.
  - Тик сервера ≤ 3 мс (медиана) при 40 ботах. Сейчас около 2,6–2,9 мс, запас маленький.

## 5. Открытые вопросы и известные шероховатости
- **Бой и баланс.**
  - Бой очень чувствителен к тому, как бойцы разбиты на отряды: если отделить 2 юнг от отряда в 48, теряется около 11 пунктов. Владелец пока не решил, смягчать ли это в движке.
  - Армии с существами против пиратов выигрывают 44–63 % (цель 45–60).
  - Пары путей на краях коридора: 42–58 %.
- **Бунт после тяжёлого абордажа** иногда всё ещё срабатывает. Проверка ждёт конца боя, но при проверках бунт видели.
- **D7 — отряды существ.**
  - Оркам и китам из `beasts.ts` отряды не нужны: они остаются морской охотой.
  - Совместного боя группы нет: группа делит награду, а дерётся один десант.
  - Пленения после боя с отрядом нет.
- **Интерфейс.**
  - Камера сильно приближена: метка в 160 м бывает за краем экрана, хотя кнопка уже есть.
  - На телефоне боком две кнопки «Осмотреть…» выглядят одинаково: имя видно только в подсказке.
  - Аудит отмечает кнопки под окном бунта на телефоне; на экране это не проверено.
- **Доход от находок.** Если плавать только ради находок на ⚓2 по часу в день, доход ×1,28 при цели ≤ +25 %.
- **Старые нерешённые решения владельца:**
  - ремонт в море стал медленным (6 % в минуту);
  - некоторые торговые рейсы платят очень хорошо.
