# 33. Эксплуатация: бэкапы, доставка ассетов, CDN, сеть, телеметрия, нагрузка

Состояние на 2026-10-16. Ветка `batch-board`.

## 1. Бэкапы базы вне сервера

### Что сделано
- **Где хранятся копии.** Каждый день зашифрованная копия базы уходит на отдельную машину: VPS в Нидерландах `31.59.220.44`, в `~/.ssh/config` он называется `vpn-nl2n`.
  - Старый сервер `abilit-old` (157.22.193.71) не подошёл: SSH к нему не отвечает ни с ПК, ни с KZ, время ожидания истекает.
  - Новые аккаунты нигде не заводились.
- **Как устроено на приёмнике.**
  - Отдельный пользователь `gtbackup` с домом в `/opt/gravetide-backups`, пароль заблокирован.
  - Ключ в `authorized_keys` ограничен так: `from="206.223.249.61",command="/usr/bin/rrsync -no-del /opt/gravetide-backups/store",restrict`.
  - Значит, с KZ можно только класть файлы в `store/`. Удалить их, получить shell или выйти за пределы `store/` нельзя, это проверено.
  - Кроме этого на приёмнике ничего не трогалось.
- **Скрипт.** `tools/ops/backup-offsite.sh`, на KZ он лежит в `/opt/gravetide/ops/backup-offsite.sh`. По шагам:
  1. Снимок базы через `VACUUM INTO`, как в `deploy.sh`.
  2. `PRAGMA integrity_check` снимка.
  3. `gzip -9`.
  4. Шифрование: `openssl enc -aes-256-cbc -pbkdf2 -iter 200000`.
  5. Загрузка через `rsync` по ssh в `daily/`. По воскресеньям копия идёт ещё и в `weekly/`.
  6. **Проверка:** скрипт скачивает копию обратно, сверяет sha256 зашифрованного файла и самой базы, расшифровывает её, делает `integrity_check` и сравнивает число таблиц и аккаунтов с исходником.
- **Хранение.** 14 ежедневных и 8 еженедельных копий. Чистит сам приёмник: скрипт `/opt/gravetide-backups/prune.sh` (копия `tools/ops/backup-offsite-prune.sh`) запускается из crontab пользователя `gtbackup` в 06:30 по Берлину.
- **Расписание.** `/etc/cron.d/gravetide-offsite-backup` на KZ, каждый день в 04:50 MSK. Лог — `/var/log/gravetide-offsite.log`.
- **Если что-то сломалось.** Любая ошибка присылает сообщение владельцу через бота игры. Токен и `TELEGRAM_ADMIN_IDS` скрипт читает из `/etc/gravetide/game.env`. Токен передаётся в curl через stdin, поэтому он не попадает ни в лог, ни в список процессов.

### Ключи (секреты в git не попадают)
| Что | Где |
|---|---|
| Ключ шифрования | KZ: `/etc/gravetide/backup.key` (root, 600). Копия для координатора: `C:\Users\enosi\.gravetide\backup-offsite.key` |
| SSH-ключ загрузки | KZ: `/etc/gravetide/backup_ssh_ed25519` (root, 600) |
| Отпечаток приёмника | KZ: `/etc/gravetide/backup_known_hosts`. Проверено, что он совпадает с ключом хоста `vpn-nl2n` |

**Ключ шифрования нужно сохранить ещё где-нибудь, например в менеджере паролей владельца.** Без него копии не расшифровать.

### Команды
```sh
ssh kz /opt/gravetide/ops/backup-offsite.sh            # сделать копию сейчас (с проверкой)
ssh kz /opt/gravetide/ops/backup-offsite.sh list       # что лежит на приёмнике
ssh kz /opt/gravetide/ops/backup-offsite.sh verify daily/gravetide-YYYYMMDD-HHMMSS.db.gz.enc
ssh kz tail /var/log/gravetide-offsite.log
```

### Восстановление
1. Выбрать копию: `ssh kz /opt/gravetide/ops/backup-offsite.sh list`.
2. Скачать и расшифровать её во временный файл. Живую базу скрипт перезаписать не даст.
   ```sh
   ssh kz '/opt/gravetide/ops/backup-offsite.sh restore daily/gravetide-YYYYMMDD-HHMMSS.db.gz.enc /tmp/restore.db'
   ```
   В ответ придёт строка `ok <таблиц> <аккаунтов>`.
3. Подменить базу:
   ```sh
   ssh kz 'set -e; systemctl stop gravetide
     cd /opt/gravetide/data
     mv gravetide.db gravetide.db.before-restore; rm -f gravetide.db-wal gravetide.db-shm
     install -o gravetide -g gravetide -m 644 /tmp/restore.db gravetide.db
     systemctl start gravetide; sleep 8; systemctl is-active gravetide'
   ```
4. **Если KZ потерян целиком.** На новом сервере нужен ключ `backup.key` из копии координатора. Файл можно забрать с приёмника по SSH под root `vpn-nl2n`: `/opt/gravetide-backups/store/daily/...`. Расшифровка:
   ```sh
   openssl enc -d -aes-256-cbc -md sha256 -pbkdf2 -iter 200000 -pass file:backup.key -in F.db.gz.enc | gunzip > gravetide.db
   ```

Полное восстановление проверено 2026-10-16:
- копию скачали с приёмника и расшифровали ключом из копии координатора;
- `integrity_check` = ok, аккаунтов 24, капитанов 22, записей в ledger 102;
- на этой базе локально поднялся сервер игры, `/` ответил 200.

## 2. Доставка ассетов
- **Листы.** `tools/art/pack_assets.py` собирает листы, перекодируя только уже готовые картинки: ничего не генерируется.
  - Листы лежат в `assets/sheets/*.webp`, карта — `assets/sheets/index.json` в формате id → [лист, x, y, w, h].
  - В листы пошли только группы, которые сцена всегда просит целиком и рисует на canvas:
    - четыре позы фигуры боя (`unit.<вид>`, `_b`, `_atk`, `_hit`): 272 листа, в среднем 4,1 запроса → 1;
    - эффекты боя `fx.bt_*`: 32 картинки, один лист.

    Частицы `part.*` в лист не пошли: море рисует несколько из них с первого кадра, и лист всех 23 стоил старту на 120 КБ больше, чем экономил бою.
  - Всего 273 листа вместо 1120 файлов: 36,5 МБ webp → 22,3 МБ в листах AVIF.
  - Клиент (`client/src/assets.ts`) загружает лист один раз и режет его на canvas по картинке. У каждого canvas выставлены `naturalWidth`/`naturalHeight`, поэтому код рендера и id не изменились.
  - `<img>` из DOM (иконки, портреты, постройки острова) по-прежнему грузят свой файл. Экран показывает несколько иконок из семейства, и лист всего семейства весил бы больше, чем экономят запросы на HTTP/2.
- **AVIF.** Рядом с каждым `.webp/.png/.jpg` и каждым листом лежит `.avif` (качество 68), если он хотя бы на 12 % меньше исходника.
  - Сервер отдаёт в манифесте версии: `a` у файла и у листа, `ma` у половинной копии.
  - Клиент один раз проверяет, умеет ли браузер AVIF (декодирует картинку 1×1), и просит `.avif`, иначе `.webp`.
  - Адреса у форматов разные, поэтому кэш, service worker и CDN не путают форматы.
- **Телефонные копии.** Половинные `.m.webp` у текстур моря были и раньше, им добавлены `.m.avif`. Выбор копии учитывает DPR: экран телефона × min(1,5, DPR) ≤ 1800 px.
- **Параллельные запросы.** На HTTP/2 и HTTP/3 (nginx gravetidegame.com) клиент держит 16 картинок одновременно вместо 6.
- **Service worker** хранит и AVIF, и листы. Список адресов, которые надо оставить при чистке, берётся из `keepUrls()`, то есть с учётом формата и листов этого браузера.
- **Замер «до/после»** (2026-10-16, телефон, Slow 4G, холодный кэш, без фоновой подкачки; одна и та же сцена — набор картинок прогона «до», оценённый так, как клиент просит их теперь):

  | Сцена | До | После |
  |---|---|---|
  | старт (HUD в порту) | 87 запр., 2599 КБ | 87 запр., 1956 КБ (−25 %) |
  | выход в море | 6 запр., 968 КБ | 6 запр., 549 КБ (−43 %) |
  | бой на палубе | 206 запр., 3235 КБ | 171 запр., 2086 КБ (−36 %) |
  | остров | 23 запр., 918 КБ | 23 запр., 628 КБ (−32 %) |

  Живые прогоны: загрузочный экран моря 3,3 → 2,0 с, острова 4,1 → 3,7 с. Старт и бой упираются в свои таймауты (12 и 7 с) и до, и после: на старте ещё ~2,4 МБ скриптов. Локальный сервер отдаёт HTTP/1.1, поэтому выигрыш от 16 параллельных запросов (только HTTP/2, прод) в эти цифры не вошёл.
- **Цена.** В репозиторий добавилось ~163 МБ: AVIF ~128 МБ, листы webp ~35 МБ. Архив деплоя вырастет примерно с 170 до ~330 МБ.
- **Как замерить:** `NOWARM=1 GPORT=<порт admin-сервера> TAG=after node tools/mobile/assets-measure.mjs`. Условия замера:
  - телефон 812×375;
  - сеть Slow 4G: 150 мс, 1,6 Мбит/с;
  - холодный кэш, без фоновой подкачки, чтобы считались только картинки самой сцены.

## 3. CDN (3 шага владельца)
Всё остальное готово:
- у версионных `/assets/...?v=` стоит `Cache-Control: public, max-age=31536000, immutable`;
- картинки отдаются с `Access-Control-Allow-Origin: *`;
- источник ассетов настраивается переменной `ASSET_ORIGIN`: клиент берёт адрес из манифеста и просит картинки с CORS.

Шаги владельца:
1. **Cloudflare.** Добавить в Cloudflare (бесплатный план) домен `gravetidegame.com` и у регистратора (hostland.ru) заменить NS на два NS, которые выдаст Cloudflare.
2. **Запись `cdn`.** В DNS Cloudflare сделать запись `cdn` → `A 206.223.249.61` с оранжевым облаком (Proxied). Режим SSL/TLS — **Full**.
3. **Сказать «CDN готов».** Дальше работа координатора:
   - выпустить сертификат на `cdn.gravetidegame.com`;
   - добавить его в `server_name` блока nginx;
   - добавить `ASSET_ORIGIN=https://cdn.gravetidegame.com` в `/etc/gravetide/game.env`;
   - `systemctl restart gravetide`.

   Откат — убрать строку из `game.env` и перезапустить.

## 4. Сеть (снапшоты)
- **Что уже было.** Снапшоты и раньше шли в бинарном виде, с интерес-менеджментом:
  - только видимое в радиусе 2200 м;
  - скрытые и игроки вне дальности обзора отсекаются;
  - частота по дистанции и по рангу (10/5/2,5 Гц);
  - 5 Гц в толпе;
  - неизменная строка не повторяется.
- **Что добавлено: кодек v7, протокол 30.** Поля передаются дельтами против того, что клиент уже держит:
  - строка корабля: varint id, маска изменённых полей, координаты как 16-битные дельты;
  - строка «себя»: 48-битная маска на 42 поля.

  Обе стороны хранят базу на соединение и сбрасывают её на `init`. Дельта без базы (если сокет пережил переход между зонами) отбрасывается целиком.
- **`pushSelf`** больше не шлёт `stats` и `effects` каждую секунду: раньше их гнали одометр и дрожание дробей в шестом знаке.
- **Замер:** `node tools/net-measure.ts --ships 20 --seconds 60`. Это один игрок в море и 20 кораблей вокруг.

## 5. Телеметрия с устройств
- **Что шлёт клиент** (`client/src/telemetry.ts`). Пачкой раз в минуту и при уходе со страницы (`sendBeacon`):
  - гистограмма FPS по сценам (море, порт, бой, остров, меню), раз в секунду;
  - время загрузочных экранов и старта;
  - ошибки JS со стеком;
  - класс устройства (система, телефон, Telegram), `deviceMemory`, JS heap.

  Личных данных нет. Единственный id — хэш случайного id, который страница завела сама, чтобы считать устройства.
- **Что делает сервер** (`server/src/http/telemetry.ts`):
  - принимает `POST /telemetry`: до 16 КБ, не больше 6 в минуту с одного адреса;
  - хранит дневные агрегаты в `data/telemetry.db`, отдельно от базы игры, и держит их 60 дней.
- **Где смотреть:**
  - `/telemetry/admin` — страница по ключу `TELEMETRY_TOKEN` из `game.env`. Ключ становится HttpOnly-cookie (это HMAC ключа), в URL он не попадает. Если ключа нет — 404.
  - `/telemetry [дни]` — в админ-консоли игры и в боте для `TELEGRAM_ADMIN_IDS`.

## 6. Нагрузка
- **Как гонять.** Только локально, не на проде:
  ```sh
  node tools/loadtest.ts --bots N ...
  ```
  Сценарий зоны — через `tools/seed-bots.ts`. Профиль снимать так: `node --cpu-prof`.
- **Что найдено и исправлено:**
  - Журнал впередсмотрящего (`recordSightings`) «молотил» при более чем 25 заметных кораблях в виду: на каждый корабль каждую секунду приходил тост каждому капитану. При 200 капитанах в гавани это была пятая часть всего сервера.
  - Сокеты капитанов на время шага теперь закупорены (cork): одна запись на сокет за шаг.
  - Записи о строках снапшота обновляются на месте, а общая строка уходит без копии.
- **Сколько игроков держит процесс.** Около 200–250 капитанов на процесс, как и раньше. Для большего — кластер (`start-cluster.bat`, зоны).
