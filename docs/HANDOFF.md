# GRAVETIDE — передача проекта (промт для новой сессии)

> Скопируйте всё, что ниже линии, в новую сессию Claude Code, открытую на репозитории `antallusion/pirates`.

---

Ты продолжаешь разработку **GRAVETIDE** — многопользовательской top-down песочницы «Pirate Gothic × Deep-Sea Horror»: океан — это мир, корабль — персонаж, капитан — билд. Все 10 фаз роадмапа (`docs/08_ROADMAP.md`) реализованы и отмечены ✅. Твоя задача — довести игру до релизного вида: **ассеты через Higgsfield**, их подключение, визуальная полировка и QA. Механики не ломать.

## 1. Репозиторий, ветка, запуск

- Репозиторий: `antallusion/pirates`. Рабочая ветка — `claude/fervent-noether-5bmdb8`: вся игра там, основной ветки на remote нет. Продолжай в этой ветке или создай от неё новую.
- **Стек:** TypeScript без сборки и **без runtime-зависимостей**. Node ≥ 22.18 запускает `.ts` напрямую (type stripping).
  - Разрешён только «стираемый» синтаксис: **нельзя** `enum`, `namespace`, parameter properties в конструкторах (`constructor(private x)`), `import =`.
  - Импорты — с расширением `.ts`.
- **Команды:**
  - `npm start` — сервер и клиент на `PORT` (по умолчанию 8080). На Windows — `start.bat`: проверяет Node, порт 58521, сам открывает браузер.
  - `npm run typecheck` — `tsc` из devDependencies. Если npm недоступен — `/opt/node22/bin/tsc -p tsconfig.json` или глобальный `tsc`.
  - `npm test` — `node:test`, 53 файла, 307 тестов. Все должны быть зелёными.
  - E2E (Playwright + Chromium, запускаются против работающего сервера): `node tools/e2e.mjs http://localhost:PORT out/`, а также `tools/e2e-onboarding.mjs`, `e2e-options.mjs`, `e2e-gamepad.mjs`, `e2e-combat.mjs`. Внутри контейнера Claude: `CHROME_PATH=/opt/pw-browsers/chromium-1194/chrome-linux/chrome`.
  - Витрины для скриншотов: `PORT=8093 SHOWCASE=<режим> node tools/showcase-server.ts`. Режимы: `boss:<id>`, `events`, `city`, `graveyard`, `maps`, `abyss`, `rich`, `port`.
  - Нагрузка: `node tools/loadtest.ts --bots 300 --seconds 60 --url ws://localhost:PORT/ws`. Профиль по подсистемам — `GET /health/profile`.
  - Воронка обучения — `GET /onboarding`. Экономика — `GET /economy`.
- **Правила:** процессы убивать только по PID (`kill $(cat pidfile)`), никогда `pkill -f`. В коммитах и коде не упоминать идентификаторы моделей.

## 3. Архитектура

```
shared/src/        общий код клиента и сервера
  data/            таблицы: ships (классы, пушки, ядра, модули, монстры), goods, factions, captains, talents + trees/,
                   crew, quests, bosses, legendary, seasons, shipbuild, holdings, deeds
  sim/             sailing (полярные диаграммы, ветер), shipstats (сборка статов из модулей и талантов)
  world/           worldgen (острова, рифы, течения, водовороты), regions
  protocol.ts      все сообщения клиент↔сервер, PROTOCOL_VERSION = 27; codec.ts — бинарные дельта-снапшоты
server/src/
  main.ts          HTTP, WebSocket, /health, /economy, /onboarding, статика
  gateway.ts       шлюз для многозонного мира; zones/ — зоны, handoff, border ghosts
  game/Game.ts     симуляция 20 Гц: step() → подсистемы; секундные проходы для сессий
  game/*.ts        combat, boarding, npc, economy, weather, bosses, events, expeditions, treasure, abyss,
                   legendary, seasons, empires, guilds, holdings, siege, pvp, onboarding, havens, …
  persistence/     SQLite (node:sqlite) или PostgreSQL; kv-хранилище для мировых систем
client/
  index.html, styles.css
  src/main.ts      вход: сеть, ввод (клавиатура по keymap, геймпад), модалки, главный цикл
  src/render/      renderer.ts (Canvas2D), gl.ts (WebGL-море и небо), atlas.ts (атлас спрайтов и
                   фракционные паруса), terrain.ts (рельеф островов), monsters.ts (процедурные монстры и
                   боссы), fx.ts (частицы с LOD), relation.ts (знаки фракций, формы отношений)
  src/ui/          hud, port, company, dialogs, crew, talents, worldmap, maps, dive, captain, onboarding,
                   options, terms
  src/assets.ts    загрузка ассетов: локальный файл → Higgsfield CDN → процедурный запасной вариант
  src/audio.ts, music.ts   весь звук процедурный (WebAudio): море, бой, музыка по состояниям, склянки
  src/settings.ts  настройки и доступность, keymap с пресетами
  src/i18n.ts, lang/       локализация RU/EN
assets/manifest.json       реестр ассетов (id → local path + CDN file + Higgsfield job id)
tools/             e2e*, showcase-server, loadtest, bot, seed-bots, fetch-assets, i18n-data, i18n-server
tests/             node:test (helpers.ts: makeGame, join, steps, FakeConn)
```

Ключевые договорённости:
- Настенное время на сервере — `game.wallNow()` (тесты подменяют).
- Мировые данные лежат в `db.getKv/setKv`.
- В профилях все новые поля нормализуются в `sanitizeProfile` через `??=`.
- Монстры и боссы — это классы с `cls.monster`. Их не двигает физика кораблей, у боссов свои модули.

## 5. Состояние ассетов — главное для тебя

**Реестр** `assets/manifest.json` — 33 ассета, сгенерированных ранее в Higgsfield (`gpt_image_2_5`, quality high):
- 14 кораблей: sloop, cutter, schooner, brigantine, fluyt, brig, frigate, galleon, man_o_war, xebec, bomb_ketch, fireship, ghost_ship, cursed_frigate;
- 6 портретов капитанов;
- 5 текстур: ocean, land, sand, chart, ebony;
- 3 реквизита: lighthouse, port_town, wreckage;
- 2 оверлея проклятия: curse_growth, curse_veins;
- `creature.leviathan`, `art.keyart`, `art.reference_captain`.

**Важно: файлы в репозиторий не выкачаны** — в `assets/` лежит только `manifest.json`. Клиент грузит картинки с CDN (`cdn` + `remote`), а без сети рисует всё процедурно. Скорее всего, поэтому у пользователя игра выглядит «процедурной».

**Как клиент использует ассеты:**
- `sprite(id)` меряет альфа-bbox изображения (`extentX/Y`, `cx/cy`) и масштабирует корабль по длине корпуса. Отсюда требования к спрайтам кораблей: **прозрачный фон, вид строго сверху, нос вверх, 2:3 вертикально, корпус по центру, без теней на фоне**.
- Корабли идут через атлас (`atlas.ts`): ячейка 256 px, вблизи рисуется полный спрайт. Паруса перекрашиваются под фракцию программно: светлые ненасыщенные пиксели считаются парусиной. Поэтому **паруса на спрайтах должны быть светлой некрашеной парусиной**.
- `tex.*` — бесшовные паттерны. Портреты 4:5 без прозрачности.

**Что сейчас процедурное и просит арта** (по приоритету):
1. **Монстры и боссы** — рисуются кодом в `client/src/render/monsters.ts` (`drawMonster`). У классов уже прописан `sprite: 'monster.<id>'`, но таких записей в манифесте нет. Нужны спрайты сверху, с прозрачным фоном, для 12 классов: `leviathan, kraken, kraken_tentacle, drowned_whale, whale_heart, lantern_maw, black_serpent, mother_of_wrecks, wreck_core, abyss_eye, hulk, storm_widow`. В `drawMonster` надо добавить «спрайт, если есть, иначе процедура» — не удаляя процедуру: она анимирует щупальца и погружение (флаги `SF.SUBMERGED`, `SF.GRABBED`, `SF.SWALLOWED`). Лучше рисовать спрайт тела и поверх процедурные анимированные части.
2. **Реквизит на островах** (`drawFeatures` в renderer.ts):
   - сейчас есть только lighthouse и wreckage;
   - нужны ruins, shrine, grove, mine, pearl bank, cache (сундук);
   - нужны порты по фракциям (crown, league, confederacy, harpoon, brokers, choir, free) вместо одного `prop.port_town`;
   - нужны постройки владений (21 id в `shared/src/data/holdings.ts`: форт, батареи, склад, таверна…) и затонувший город / кладбище кораблей для PvE-локаций.
3. **Иконки интерфейса** (сейчас текст и Unicode):
   - 24 товара, 6 боеприпасов, 5 пушек, 5 палубных установок, 17 модулей, 9 фигур на нос;
   - 24 способности капитанов, иконки деревьев талантов;
   - знаки 7 фракций (сейчас Unicode ♛ ⊖ ⚔ Ω ↟ @ ⚓ в `render/relation.ts` — оставить как запасной вариант);
   - маркеры карты мира.
4. **Портреты:** 6 уникальных офицеров (`crew.ts` → UNIQUE_OFFICERS), наставники Путей, «карточки» 10 боссов для панели HUD `#hud-boss`, 5 легендарных кораблей (`legendary.ts`: first_rib, saint_maws_bell, crowns_sorrow, widows_lament, lamplighter).
5. **Текстуры** регионов и биомов островов: volcanic, ice, bone, ruins, mossy (сейчас один `tex.land` плюс тинт по биому в `BIOME_TINT`), пергамент карты мира.
6. **Эффекты:** дым, огонь, брызги, щепа сейчас процедурные частицы — можно заменить спрайт-листами. Держать бюджет: у частиц есть LOD.

## 6. Пайплайн ассетов (как делать)

1. Читай `docs/06_ART_DIRECTION.md` целиком, особенно §1 (эталон), §3 (правило 80/20 — странного в кадре не больше бюджета региона), §4 (палитра), §17 (пайплайн).
2. **Генерация:** Higgsfield MCP-инструменты `generate_image` / `generate_image_batch`, затем `jobs_wait` и `show_generation_by_ids`.
   - Модель `gpt_image_2_5`, quality high.
   - Прозрачный фон — для всех спрайтов.
   - Промпты строй по шаблонам §17.4: единый стиль, указание «top-down orthographic», нос вверх, соотношение сторон.
   - Если нужна вырезка фона — `remove_background`.
   - Генерируй пачками, кураторь: в игру попадает только отобранное.
3. **Регистрация:** запись в `assets/manifest.json` вида `"<группа>.<id>": { "local": "<папка>/<id>.png", "remote": "<файл на CDN>", "job": "<id задачи Higgsfield>" }`. Именование — по §17.3.
4. **Выкачать в репозиторий:** `npm run assets:fetch` (`tools/fetch-assets.ts` кладёт файлы в `assets/<local>`), затем закоммитить PNG. Так игра будет работать офлайн. Проверь размеры: крупные картинки ужми до разумного (корабли ~512–768 px по длинной стороне, иконки 128–256).
5. **Подключение в коде:** `sprite('<id>')` из `client/src/assets.ts`. Всегда оставляй процедурный fallback — игра обязана рендериться, даже если все загрузки упали.
6. **Проверка:**
   - typecheck, `npm test`, `tools/e2e.mjs` (массив `errors` должен быть пустым);
   - скриншоты витрин (`SHOWCASE=boss:kraken`, `abyss`, `port`, `events`…) — посмотри их глазами;
   - сравни с эталоном из §1 docs/06.

## 7. Другие известные хвосты (не обязательно, но полезно)

- **Названия портов** в интерфейсе остаются латиницей (Saltmarrow…), а транслитерации есть в `client/src/lang/data.ru.ts` (`regions.KEY_PORTS.*.name`). Можно выводить через `NAME_RU`.
- **Локализация серверных фраз.** Клиент сопоставляет английский текст с шаблонами (`client/src/lang/server.ts`, таблицы `server.ru.a.ts` / `server.ru.b.ts`). **Любая новая фраза, которую сервер говорит игроку, должна получить русский вариант.** Список шаблонов выдаёт `node tools/i18n-server.ts`. Тест `tests/i18n-coverage.test.ts` падает, если без перевода больше 2% фраз. Новые тексты данных — через `tools/i18n-data.ts` → `data.ru.ts` / `data.talents.ru.ts`. Экранные тексты — в словарях `client/src/lang/ui/<экран>.ts` (`dict(EN, RU)`).
- **E2E в headless** рендерит WebGL через SwiftShader, медленно. Ожидания в тестах должны быть терпимыми к низкому FPS.
- **Процедурные замены.** Если добавляешь спрайт для того, что сейчас рисует процедура, процедура остаётся запасным путём.
- **Цвета.** Палитры для цветовой слепоты (`settings.ts → cbColor`) переопределяют «смысловые» цвета. Новые смысловые цвета в арте (опасность, аномалия) должны читаться и в этих режимах: всегда форма плюс цвет (docs/07 §11).

## 8. Как работать

- После каждой завершённой единицы работы: typecheck → `npm test` → e2e при изменениях клиента → коммит → push.
- Коммиты в той же ветке (`claude/fervent-noether-5bmdb8`) или в новой от неё. Сообщения — по сути изменения.
- Не ломать существующие механики и тесты. Новое покрывать тестами, где это логика; для арта — скриншотами витрин.
- Сделанное отмечать в `docs/08_ROADMAP.md` (при желании заведи раздел «Phase 11 — Art pass»).
- Начни с шага 5.0: выкачай существующие 33 ассета (`npm run assets:fetch`), закоммить их, прогони e2e и посмотри скриншоты. Потом бери по приоритету: монстры и боссы → реквизит островов и порты фракций → иконки интерфейса → портреты → текстуры биомов → эффекты → keyart.
